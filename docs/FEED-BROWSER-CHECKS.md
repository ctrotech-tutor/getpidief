# Feed browser checks

`tests/browser/feed.spec.ts` is a separate opt-in Playwright suite for the **fictional local seed**. It signs in as `learner01@example.test`, intentionally tests failed like and follow requests, then performs successful likes, reposts and a follow which it attempts to undo. It must only run against an isolated, disposable application and database. It is not a test for production or shared environments.

1. Create an isolated local database, run migrations and the local seed as described in [LOCAL-SEED.md](LOCAL-SEED.md). Verify the application and all its services point to local development resources, not hosted data. Start the local application separately.
2. Install the Chromium browser normally for Playwright: `npx playwright install chromium` (or configure `FEED_BROWSER_EXECUTABLE` to an existing compatible Chromium executable). In environments without required system libraries, install those through your normal development setup.
3. Run `FEED_BROWSER_TEST=yes npx playwright test --config=playwright.feed.config.ts`. The default origin is `http://localhost:3000`; `FEED_TEST_BASE_URL` may specify another HTTP loopback origin. This is only a guardrail: a loopback proxy or tunnel can still lead to a remote app/database. Explicitly verify the target before running. The suite never starts a server or resets a database. Artifacts are stored under ignored `.next/feed-browser-results`.

The suite covers desktop and emulated mobile Chromium: the shell and back navigation, overflow, optimistic like rollback during a stalled/failing request, successful optimistic likes and reposts with persistence, menu text/icon contrast on highlight, keyboard menu dismissal, and manual pagination with a delayed API response, visible posts and an announced loading state. On desktop it also tests failed-follow rollback and a successful follow updating the people rail without replacing the feed. It waits for the successful follow response and attempts cleanup in `finally`; an interrupted run can leave interactions or a follow in the **disposable** database.

A local run on the seeded dataset passed 12 checks (two desktop-only rail cases were skipped on mobile). This is not an accessibility audit, real-device testing, a slow initial server-render test, full keyboard/screen-reader coverage, or Firefox/Safari coverage. Backend rate limits, failure modes, real production traffic and hosted services still need independent validation. Do not expose the seeded known-password application or database as a public service.
