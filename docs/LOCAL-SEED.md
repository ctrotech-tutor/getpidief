# Local development dataset

`npm run db:seed` creates a review dataset in a **local development database only**, after migrations have been applied. It replaces the old seed script; it does not delete or replace data that the old script previously inserted. It never resets a database or runs migrations. Check the actual `DATABASE_URL` first, including shell-exported values which take precedence over `.env.local`.

**These are fictional people and simulated activity, not real users or genuine community engagement.** Fifty actual credential accounts are created, `learner01@example.test` through `learner50@example.test`, initially using `Password123!`. The first run marks their emails verified and onboarding complete without sending email, and inserts approved demo resources directly. This is a deliberate test shortcut, not a test of signup, moderation, upload storage or email delivery. No administrative accounts or claims of institutional affiliation are created.

The script inserts 120 original example posts, 120 example replies, demo-to-demo follows, likes, saves and interests, plus eight original short educational PDFs in `public/seed-assets/`. The notes contain original demo text and links to further reading, including official public sources. The links are not downloaded, rehosted or represented as publications authored by the fictional accounts. Their availability and licensing may change. PDF files are generated locally, ignored by Git and served as public static files; do not place sensitive material there. These are **not uploaded PDFs** and do not test UploadThing access control or the normal review pipeline. Real third-party PDF ingestion requires separate rights, attribution, storage, privacy and moderation review.

## Run

1. Confirm `DATABASE_URL` is an isolated local development database, not production or a tunnel to a remote server. The script rejects non-loopback URLs, URL parameters and `NODE_ENV=production`, but cannot determine what is behind a local tunnel. Never expose this database or these known-password accounts to the internet.
2. Start PostgreSQL and apply the existing migrations only to your chosen local database: `npm run db:mig`.
3. Run `npm run db:seed`, then `npm run dev`. Sign in with `learner01@example.test` and `Password123!`. Other demo accounts follow some of the 50 accounts; your own existing account does not automatically follow them.

The script uses stable UUIDs (`scripts/seed/identity.ts`) for future fixture associations, a transaction and an advisory lock. It refuses conflicting accounts or content IDs and does not overwrite existing passwords or profile details. Derived follow and document counts for demo profiles are recalculated from actual rows. Reruns fill missing fixtures, which can restore removed demo follows, interests and reactions; they do not update edited or deleted demo posts. If you changed a demo password, a rerun does not reset it. Do not assume rerunning is a clean reset. Generated files can remain if a DB transaction fails. Existing files are never overwritten; if one differs from the fixture, the seed stops so it can be reviewed. Real user rows are not deleted or modified.

The source modules separate identity, guardrails, original content and PDF generation. The target guard is intentionally restrictive and does not support hosted databases or Docker service hostnames. For testing against disposable PostgreSQL only, the integration test accepts `TEST_SEED_DATABASE_URL` pointing to an **empty**, local database ending in `_seed_test`, after migrations, and requires `TEST_DATABASE_WRITE=yes`. It creates data and intentionally does not delete it afterward.
